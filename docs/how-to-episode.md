# 1話の作り方（手順書）

2章（第9〜17話）を作ったときの実際の手順を、次の章（3章）や化学でもそのまま使えるようにまとめたものです。ルールの細かいところは `CLAUDE.md`、タスクの出し方は `docs/tasks.md` を見てください。

## ぜんたいの流れ

```
① 脚本と設計表（docs/story-chN.md）── ぱかちんが読んで OK
        │
        ├─ ② ストーリー（story/epXX.js）   ┐ ②と③は同時に作れる
        ├─ ③ シミュ（sim/xxx.html）        ┘（さわるファイルが別）
        │
        └─ ④ ドリル（physics/app.js など）── ②③のあと（場面・数値をそろえる）
                │
                ⑤ つなぐ → ⑥ チェック → ⑦ 報告とプルリクエスト
```

1章ぶん（8〜9話）なら、タスクはこう分けるとちょうどよい（2章の例）。

| タスク | 中身 | 待つもの |
| --- | --- | --- |
| T-10 | ① 脚本と設計表 | なし |
| T-11 | ② ストーリー全話 ＋ `story/list.html` | T-10 の OK |
| T-12 | ③ シミュ全部 ＋ `sim/index.html` | T-10 の OK（T-11 と同時でよい） |
| T-13 | ④ ドリル ＋ ⑤ つなぐ | T-11・T-12 がマージされてから |

## ① 脚本と設計表　`docs/story-chN.md`

- 教科書（東京書籍）の章の流れにそって、1テーマ1話にする。番号は章をまたいで通し番号
- いちばん上に**設計表**（話・狙う誤概念・シミュ案・ドリル）。今あるドリル単元との対応も書く（ないものは「新規」）
- 各話は同じ型：**ねらい → 謎（〈画〉とセリフ）→ 予想（〈選〉3つ）→ 紙芝居（【場面】4〜6）→ 種明かし（答え・ポイント）→ 次へ**
- いちばん下に**計算メモ**（脚本に出てくる数値を全部、式と答えで）
- ここで決めた**数値がシミュ・ドリルの最初の値**になる。スッキリ割り切れる数にしておく
- ぱかちんの OK が出るまで、②〜④は作らない

## ② ストーリー　`story/epXX.js`（`story/list.html`）

見本：`story/ep03.js`（短くて読みやすい）。プレイヤー `story/index.html` はさわらない。

1. 1章の脚本ファイルの頭の「道具」（`svg` `T` `anim` `answerCard` `SKY`）をそのまま使う
2. その話の絵を `SCENES['eN-なまえ']` に足す（名前は話の番号で始めて、ほかの話とぶつからないようにする）
3. `window.EPISODE` を書く：`id`・`chapter`・`topic`・`title`・`simUrl`・`drillUrl`（2つ以上なら `drillUrls`）・`scenes`
4. `scenes` の並び（2章の形）

| 場面 | 書き方 |
| --- | --- |
| タイトル | `{ bg: 'title' }` |
| 謎と予想 | `choice: { id, options: [3つ], answer }` |
| リカの反応 | `byChoice`（選んだ答えごとにセリフと表情） |
| ニュートンくんの反応 | `byChoice` |
| アニメで確かめる | `anim()` の絵＋ `byChoice` |
| 答え合わせ | `{ bg: 'eN-answer', reveal: 'q1', right, wrong }` |
| くわしく見る | 2〜5場面 |
| まとめ | `{ bg: 'end', end: true, points: [3つ] }`（points は脚本の「ポイント」） |

5. `story/list.html` に章の見出しと話を足す
- 1場面のセリフは短く（50字くらいまで。長ければ2場面に分ける）
- ドリルがまだない話は `drillUrl` を書かない →「チャレンジモード（準備中）」が出る

## ③ シミュ　`sim/xxx.html`（`sim/index.html`・`sim/medal.js`）

見本：`sim/speed-race.html`、2章なら `sim/motion-equation.html`。

1. 1ファイル。上から：ヘッダー → 見出し → ニュートンくんのひとこと → 実験台（SVG・表・式）とそうさ → ミッション（3こ）→ わかったこと → リンク
2. 最初の値で脚本の数値が出るようにする（例：第14話 2.0 kg・4.0 N → 2.0 m/s²）
3. ミッションは、**実際のクリック・スライダーで達成できる**ものにする
4. メダルにつなぐ（3つ）：`<script src="medal.js"></script>` を読む／`showMissions()` の最後で `SimMedal.sync(done);`／`sim/medal.js` の `SIMS` に1行
5. `sim/index.html` に章の見出しと話の順で足す
- 2章では、同じ骨組みを書き出す道具（build.py）で9本をそろえた。CSS・共通の関数（矢印・アニメ・ひとこと）は1章のシミュと同じ
- 力の矢印の色は全部でそろえる：重力＝紺、人が加える力＝赤、支える力（垂直抗力・張力・弾性力・浮力）＝木、まさつ力＝うすい木、合力＝赤の点線

## ④ ドリル　`physics/app.js`（`physics/index.html`・`physics/mypage.html`）

1. 問題を作る関数を書く（返すもの：`badge` `text` `formula` `inputs` `result` `anim` `ap`、向きのある問題は `signed: true`）
   - 問題文は**話の場面**で（「リカが…」「ニュートンくんが…」）、数値は場面に合うはんいで
   - 向きがある量は「○向きを正とする」を問題文に書く
2. `unitMap` に単元を登録。**新しい単元は番号のうしろに足す**（番号をずらすとマイページの記録がずれる）
3. 動く絵を `STORY_DRAW` に足す（右はしにキャラ、色はストーリー・シミュと同じ）
4. `STORY_EP`（📖 第◯話の札）と `SIM_EP`（シミュから来たときの「← 第◯話のシミュにもどる」）に登録
5. 単元一覧 `physics/index.html` のカード（📖 第◯話）と、マイページ `physics/mypage.html` の `UNITS` に足す

## ⑤ つなぐ

| どこから | どこへ | 書く場所 |
| --- | --- | --- |
| ストーリーの最後 | シミュ・ドリル | `story/epXX.js` の `simUrl`・`drillUrl(s)` |
| シミュの下 | ドリル・ストーリー | `sim/xxx.html` の `.links` |
| シミュのヘッダー | ストーリー | `../story/?ep=XX` |
| ドリル | もとの話・シミュ | `STORY_EP`・`SIM_EP`（自動で「← もどる」が出る） |

## ⑥ チェック（スマホ幅 390px）

- [ ] 物理の数値を全部計算して、報告に表で書いた（脚本・シミュ・ドリルで同じ数か）
- [ ] ストーリー：**全部の選択肢**で最初から最後まで進める（ふつうの設定と「動きを減らす」設定の両方）
- [ ] シミュ：実際の操作でミッション3こを達成 → メダル・トロフィーの箱が出る
- [ ] ドリル：単元ごとに10問解く（計算モードで全部正解 → トロフィー）。問題をたくさん作って、答えと式が合うか、`undefined`・`NaN` がないか
- [ ] つないだリンクを全部たどる（ストーリー → シミュ → ドリル → もどる）
- [ ] 横にはみ出さない、コンソールのエラーがない
- [ ] 色は `CLAUDE.md` の配色だけ（新しい色がないか）
- [ ] 絵の中で文字・矢印が重なっていないか（スクショを見る）
- [ ] スクショを `docs/reports/T-○○/` に置いた

## ⑦ 報告とプルリクエスト

- `docs/reports/T-○○.md`：やったこと → スクショ → ぱかちんが決めること（選択肢つき）→ 計算チェック → さわっていないもの
- `docs/tasks.md` の自分のタスクの行だけ `[x]`
- 専用ブランチ → プルリクエスト（マージはぱかちん）

## 化学でちがうところ（化学1章を作るときに足す）

- 番号：ストーリーは `story/chem01.js`〜、ドリルの単元は「化1-1」〜
- キャラは化学もニュートンくんとリカ。ニュートンくんの錬金術（「金は作れるのか？」）が全話を通す筋（`docs/chem-story-ch1.md`）
- 化学のドリルは選ぶ問題が多い（純物質か混合物か、炎の色、状態変化の名前など）。物理のドリル（数を入れる）とは別の土台を使う
- 「力の矢印の色」のかわりに、粒子・物質の色を化学用にそろえる（化学1章のシミュを作るときに決める）
